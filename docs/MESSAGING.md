# 消息通道方案：通知 + 审批反馈（多 IM 适配，配置驱动）

> 状态：**方案确认中**（2026-08-20 老板讨论定稿，待开发）
> 定位：平台消息能力（告警通知 + 审批通知 + 审批反馈），支持钉钉/企微/飞书，传输模式与反馈方式全部**功能内配置**（不依赖部署环境区分，代码全实现，运行时按配置生效）
> 目标：开源项目友好——全 IM 支持、无公网/有公网环境都可用

## 老板拍板的决策（2026-08-20）

1. **全 IM 支持**：钉钉 / 企微 / 飞书，都支持（开源考虑）
2. **传输模式功能内配置**：长连接（无公网）/ Webhook 回调（有公网），平台配置界面选择，不是文档区分
3. **反馈双通道**：文本回复（`批准/拒绝 + 审批ID`）+ 卡片按钮（点一下），各 IM 能力内都做
4. **审批不需要平台上公网**：默认长连接模式，移动端审批无公网可用
5. **配置全部平台化**：webhook/secret/传输模式/反馈方式/连接参数，通知配置页统一管理

## 一、消息通道适配层

```
告警通知 / 审批通知 / 审批反馈
          ↓ 统一接口（发送 + 接收反馈）
    消息通道适配层
          ├─ 钉钉适配：Webhook 发送 + Stream 长连接 / 回调接收
          ├─ 企微适配：Webhook 发送 + 回调接收（长连接后续）
          └─ 飞书适配：Webhook 发送 + 长连接 / 回调接收
          ↓
    回调/长连接事件 → 验签 → 解析 → 审批处理（handle_callback）
```

## 二、传输模式（每渠道配置选择）

| 传输模式 | 适用环境 | 说明 |
|---|---|---|
| **长连接** | 无公网（默认） | 平台主动连 IM 服务器（钉钉 Stream / 飞书长连接），事件推送走长连接 |
| **Webhook 回调** | 有公网 | 平台开回调端点，IM 服务器回调；需公网可达地址 |

- 每渠道独立选择，切换即时生效
- 长连接断线自动重连 + 事件补偿（断线期间主动拉取补发）
- 均无法触达时：网页审批兜底（平台内审批页）

## 三、各 IM 能力矩阵

| IM | 发送通知 | 文本回复反馈 | 卡片按钮反馈 | 长连接（无公网）| 回调（公网）|
|---|---|---|---|---|---|
| **钉钉** | ✅ webhook | ✅（@机器人）| ✅ Stream 模式 | ✅ Stream | ✅ |
| **飞书** | ✅ webhook/个人消息 | ✅ | ✅ | ✅ 长连接 | ✅ |
| **企微** | ✅ webhook | ✅（@应用）| ⚠️ 需企业应用 | ❌ 官方无 | ✅ |

- 企微无公网环境：审批反馈引导至钉钉/飞书或网页审批（通知发送不受影响）

## 四、审批反馈流程

```
审批通知发出（含审批ID）
   ↓
值班人反馈（按配置模式）
   ├─ 文本回复："批准 123" / "拒绝 123 原因"
   └─ 卡片按钮：点 [批准] / [拒绝]
   ↓
长连接事件 / 回调 → 验签（secret/token）→ 解析审批ID+动作
   ↓
身份映射（dingtalk_user_id / wechat_userid / feishu_user_id → 平台用户）
   ↓
更新审批状态（幂等：source_msg_id 去重）
   ↓
通过 → 执行 / 拒绝 → 终止转人工
```

## 五、平台配置项（通知配置页）

| 配置 | 说明 |
|---|---|
| webhook 地址 + secret | 发送用（现有 notification_configs 扩展）|
| 传输模式 | 长连接 / 回调（每渠道选）|
| 反馈方式 | 文本 / 按钮 / 都支持 |
| 长连接参数 | 如钉钉 Stream appKey/appSecret、飞书长连接配置 |
| 回调地址 | 回调模式时配置/展示 |
| 测试按钮 | 发送测试消息验证连通 |

- 全量留痕（NotificationLog：谁/何时/渠道/内容/结果）
