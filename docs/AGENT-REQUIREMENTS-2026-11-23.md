# AI Agent 需求规格（2026-11-23）

> 老板口径：**故障 → 先分析 → 告警（带原因）→ 能自己解决就解决 → 不能转人工**；自己解决必须说清具体原因；生产环境有用户感知的操作必须人工确认，无感知不需审核。
> 本文是可直接开发的需求规格。上级文档：`AGENT-GOAL-2026-11-23.md`（目标）、`AGENT-AUTONOMY.md`（边界）、`REQUIREMENT-GUIDE.md`（写法规则）。
> 验收用例：`docs/cases/CASE-*.md`。

---

## 一、现状与差距（一句话）

平台现在**会看、会想、不会动手**：诊断能力（17 个只读工具 + 单次 LLM + ReAct 骨架默认关闭）已具备，但执行动作只有「删 Pod / 补镜像凭据 / 调探针」三个硬编码分支，且存在两处违反新口径的旧逻辑（盲试重建、命中代码特征跳过分析）。

---

## 二、总体设计

```
发现故障
  ↓
【强制】分析原因（必须出「具体原因+证据+把握度」）
  ↓
告警（携带结论；紧急故障两段式）
  ↓
三条件判定：有手段？有把握？生产是否无用户感知？
  ├─ 全满足 → 自主执行 → 验证 → 收尾
  └─ 任一不满足 → 转人工（附原因/证据/建议/已排除项）
```

**四档边界**（详见 `AGENT-AUTONOMY.md`）：🟢免审自动 / 🟡免审报备 / 🔴必须审批 / ⛔永不执行。

## 三、能力需求

### R68 故障统一入口 + 先分析后告警（P0，2d）

| 项 | 内容 |
|---|---|
| **触发** | 告警源上报 / 定时巡检发现异常 / 人工提问 |
| **行为要求** | ① 任何来源的故障先转成统一结构：`对象(集群/ns/资源) + 现象 + 首次出现时间 + 影响面 + 当前状态`；② **告警必须携带分析结论**，禁止只发「服务挂了」；③ 紧急故障（服务不可用）采用两段式：立即发「已发现故障，正在分析」，分析完成 ≤90s 内补发结论；④ 非紧急故障（趋势/巡检类）分析完一次性发出；⑤ 分析失败也必须发告警，内容为「已排除 A/B/C + 缺失证据 D + 建议人工查 D」 |
| **质量门槛** | 抽查 20 条告警，携带「原因+证据+把握度」的比例 **100%**；告警字段缺失（现象/时间/原因/证据/把握/处置/影响面 七项）为 0 |
| **失败行为** | 分析超时 → 先发「正在分析」告警，再发「分析超时，已排除…」；结构转换失败 → 按原始告警发出并标记「未结构化」 |
| **验收用例** | CASE-001 / CASE-003 / CASE-006 |
| **依赖** | 无（可并行） |

**告警必含七字段**：现象、时间、原因、证据、把握度、已做处置、影响面。

---

### R69 通用诊断循环（P0，3d）

| 项 | 内容 |
|---|---|
| **触发** | R68 的每个故障；人工提问 |
| **行为要求** | ① 自主决定每一步查什么、查几次（不预设步骤）；② 必须与「正常态」对比（上一正常版本 / 历史基线 / 同类服务）；③ **必须先形成具体原因，才允许进入处置**；④ 禁止「先重启试试」；⑤ 步数未用完不得下结论；⑥ 禁止「建议检查近期变更」类空结论；⑦ **下线两处旧逻辑**：`_try_rebuild_once` 的盲试重建、`_match_app_crash` 命中即跳过分析转人工 |
| **质量门槛** | 20 个历史故障回放：根因吻合 ≥ **16 个（80%）**；平均步数 ≤8、上限 12；平均耗时 ≤90s；无证据结论 **0** |
| **失败行为** | 达上限 → 输出「已排除项 + 缺失证据 + 建议人工查什么」，不得猜测；工具报错 → 换等价工具重试 1 次后如实报告；数据缺失 → 指明缺什么、需谁提供 |
| **验收用例** | CASE-001 / CASE-002 / CASE-003 / CASE-004 / CASE-005 / CASE-008 |
| **依赖** | R60 的版本/发布查询工具（已有：list_revisions / compare_revisions / get_workload_events_timeline） |

### R70 动作库（手段清单）（P1，2.5d）

| 项 | 内容 |
|---|---|
| **触发** | R69 得出结论后，需要处置时 |
| **行为要求** | ① 每个手段登记 5 项属性：适用条件、执行方式、风险档（🟢🟡🔴⛔）、验证标准与时限、回滚方式；② agent 自行匹配手段，**不预枚举故障类型**；③ 新增手段只改配置，不改 agent 主流程；④ 首批手段：重建单 Pod / 删除卡死 Pod / 多副本滚动重启 / 回滚到上一正常版本 / 补镜像拉取凭据 / 摘流；⑤ **新建「回滚」执行通道**（executor 侧 `rollout undo` 等价实现，当前不存在） |
| **质量门槛** | 首批 6 个手段各有 ≥1 次成功案例；动作成功 ≥85%；**二次故障 0**；新增手段不动 agent 代码（评审确认） |
| **失败行为** | 无匹配手段 → 不执行，转人工并说明「缺什么手段」；手段执行报错 → 停手，不换第二个动作硬试 |
| **验收用例** | CASE-001（回滚）/ CASE-002（补凭据）/ CASE-003（重建）/ CASE-007（强删） |
| **依赖** | executor 回滚通道（新增，1d）；api-server 动作注册表 |

---

### R71 自主处置三条件闸门（P1，1.5d）

| 项 | 内容 |
|---|---|
| **触发** | R70 选定手段后，执行前 |
| **行为要求** | 三个条件全满足才自主执行：① **有手段**（动作库匹配到）；② **有把握**（confidence ≥ 生产 0.8 / 测试 0.6）；③ **生产环境无用户感知**（R72 判定）。任一不满足 → 转人工，携带原因/证据/建议动作/已排除项。每次决策必须记录：判定档位、把握度、依据 |
| **质量门槛** | 回放 20 个故障：误判「可自动」**0**；漏判「需审批」**0**；自动执行的动作 100% 能追溯到原因分析记录 |
| **失败行为** | 判定数据不全（副本数/探针/策略缺失）→ **一律按有用户感知处理**；把握度处于阈值边界（±0.05）→ 转人工 |
| **验收用例** | CASE-009（单副本/多副本对照）/ CASE-010 |
| **依赖** | R69 + R70 + R72 |

---

### R72 用户感知判定 + 生产审批（P1，1.5d）

| 项 | 内容 |
|---|---|
| **触发** | 生产环境任何处置动作执行前 |
| **行为要求** | ① 按数据自动判定是否产生用户感知：**无感知** = 副本≥2 + 滚动更新 + 有就绪探针 + 执行期间始终≥1 就绪副本 + 非缩容/非节点操作；**有感知** = 单副本 / 无就绪探针 / 一次性全重启 / 缩容或超 2 倍扩容 / StatefulSet 单点 / 节点操作 / 改探针或配置导致重启；**判不准一律按有感知**；② 有感知 → 推送审批，审批人 = 服务负责人或值班，生产不可逆操作双人；③ 超时默认**拒绝**并上报；④ 同一服务 10 分钟内只自动处置 1 次 |
| **质量门槛** | 单副本服务触发重启 → 走审批 **100%**；多副本滚动操作 → 免审 **100%**；误判为无感知导致用户可见中断 **0** |
| **失败行为** | 副本数/探针/更新策略读不到 → 按有感知；审批被拒 → 停止且不换招；审批超时 → 停止并上报 |
| **验收用例** | CASE-009 / CASE-011 |
| **依赖** | R71 |

---

### R73 执行验证 + 结果沉淀（P2，2d）

| 项 | 内容 |
|---|---|
| **触发** | 每个动作执行后 |
| **行为要求** | ① 每个手段自带验证标准（Pod 就绪 / 崩溃消失 / 指标回落 / 请求成功率恢复）与时限（默认 180s，回滚 300s）；② 验证未通过 → **立即停手，不尝试第二个动作**，转人工并如实报告「已执行 X，未恢复」；③ 每次处置（自主成功 / 人工修复）记录 `现象 → 原因 → 动作 → 结果 → 耗时` 入知识库；④ 同类故障再次出现时优先复用历史方案，并标注来源 |
| **质量门槛** | 验证未通过的场景 100% 停止且如实上报；同类故障第二次处理步数下降 ≥50%；人工修复案例回填率 100% |
| **失败行为** | 验证手段本身不可用 → 报告「无法验证」，按失败处理转人工，不默认成功 |
| **验收用例** | CASE-004（验证内存/重启次数）/ CASE-012（版本修复后验证） |
| **依赖** | R71 + R72 |

## 五、验收总表

| 项 | 标准 |
|---|---|
| 告警质量 | 20 条抽查 100% 含原因与证据 |
| 诊断准确率 | ≥80%（20 例回放） |
| 自主解决 | ≥8/20，二次故障 0 |
| 禁止盲试 | 每条自动动作均可追溯原因（无原因 = 违规） |
| 用户感知判定 | 单副本 100% 审批 / 多副本 100% 免审 |
| 失败停手 | 验证失败必停手并如实上报 |
| 转人工质量 | 单据含原因/证据/建议/已排除项，缺一计失败 |

**一票否决**：无证据结论、误判可自动、造成二次故障。
