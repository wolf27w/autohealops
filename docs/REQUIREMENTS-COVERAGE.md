# AutoHealOps 需求覆盖对照（需求 → 现有系统能解决什么）

> 整理：小吴　2026-11-04
> 依据：`ROADMAP.md` / `REQUIREMENTS-BACKLOG.md` / `NEW-REQUIREMENTS-*.md` / `AGENT-ONLY-ARCHITECTURE.md` + **代码与运行中数据库实测**
> 口径：✅ 已能解决（有页面 + 接口，实测可用）｜🟡 部分解决（有底座，缺一环）｜❌ 解决不了（需外部条件/未开发）

---

## 一、一句话结论

平台已经把**「告警产生 → 去重降噪 → AI 诊断 → 决策 → 审批 → 自愈执行 → 验证 → 工单/通知 → 复盘沉淀」**这条主链路完整闭环了，
日常 80% 的运维问题（Pod 故障、资源水位、节点异常、DB 慢查询、日志关键字）都能在系统内从发现走到处理完。
**解决不了的是三类**：跨公网纳管（agent 隧道没加密/没对外）、集群侧依赖（exporter / 准入 webhook）、以及平台自身尚未上生产。

## 二、按问题域对照

### 1. 集群太多、接入和凭据管理麻烦

| 我要解决的问题 | 现有系统怎么解决 | 状态 |
|---|---|---|
| 多个集群统一纳管 | 集群管理页：kubeconfig 单份 / 多 context 批量导入 / agent 令牌接入；`clusters.source` 区分 kubeconfig·in-cluster·agent | ✅ |
| 云原生权限（不用 cluster-admin） | 专项 B：Impersonation + 自动下发三档 ClusterRole + RoleBinding 对账 | ✅ |

| 平台自己住在集群里还要传 kubeconfig | in-cluster 自接入（启动自动 upsert + 「本集群」标记） | ❌ P3 未做 |
| 接入后集群是否活着 | 定时健康检查 + 状态列 + 掉线判定 | ✅ |

### 3. 告警太多、太吵、没人认领

| 同一问题刷屏 | 三路合并：`dedup_key` + 窗口内已解决告警 reopen + `event_count`；历史 1797 行已归并为 1112 行（重复分组 0） | ✅ |
| 告警风暴 | 风暴抑制 + 30 分钟限流 + 静默窗口 + 未解决 ≥10 推汇总 | ✅ |

| 通知要能到人 | 钉钉/企微/飞书（webhook + 应用模式）/ 邮件 / 站内消息中心；模板按渠道分字段；@值班人 | ✅ |

### 4. 出问题不会查（智能诊断）

| 我要解决的问题 | 现有系统怎么解决 | 状态 |
|---|---|---|
| 故障要自动给结论 | 告警触发即诊断；故障 / 应用 / 数据库三类彻底分开（入口、数据、知识库、报告、权限独立） | ✅ |
| 诊断太慢/太贵 | 快速诊断（知识库优先 + 平台预采集 + 单轮）默认走；深度诊断（多轮工具）可选；同一问题 30 分钟内复用不重复调 AI | ✅ |
| 诊断要有真凭实据 | 预采集注入：Pod/节点指标趋势（60 分钟 min/max/avg）、探针真实参数 + 容器内实测健康端点、JVM 证据、Deployment 参数、事件、日志 | ✅ |
| 诊断结论要能积累 | 诊断出根因即沉淀知识库（0.9 相似度去重）；人工 👍/👎 + 隐式反馈（修复验证结果）回写质量指标 | ✅ |
| 诊断失败要能看见 | `diagnosis_failures` 独立表（阶段/原因/模型/次数）+ 前端「诊断失败记录」 | ✅ |
| 想主动巡检，不等告警 | 巡检服务：持续高水位/频繁重启但无告警 → 自动全面诊断（不建告警）；平台 30 分钟一轮 + AgentChat「立即巡检」 | ✅ |
| 想直接问系统 | 应用诊断助手（AgentChat）：自由 PromQL、集群/ns/Pod/容器下拉、断线续传、知识库记忆 | ✅ |

## 三、现有系统「解决不了」的部分（及原因）

| 项 | 为什么解决不了 | 缺什么 |
|---|---|---|
| 跨公网纳管客户集群（agent-only） | 隧道明文 gRPC、9095 无对外入口；agent 镜像未构建 | P4 TLS + 四层转发 + agent 镜像 |
| 平台入住即自动纳管本集群 | 无启动 upsert | P3-a（~1.5–2d） |
| agent 版本可见/灰度/回退 | `agent_version` 只读不写，无升级 API | P3-b（~1–1.5d） |
| agent 集群上的终端/自愈/批量 | 3 个流式 RPC 未代理（`ExecutePlan`/`BatchExecute`/`ExecPodStream`） | 流式隧道（~1–2d） |
| 中间件指标告警 | 指标模板在，集群里没有 exporter | 集群侧部署 |
| 准入控制（MutatingWebhook） | admission 模块已从代码删除 | 需重新决策是否做 |
| 大表继续增长 | `pod_metrics` 233 万行等未分区 | 运维窗口 DDL |
| 多时区 | 全链路固定 Asia/Shanghai | 暂缓（单时区无收益） |

## 五、结论

- **已闭环的能力**：集群纳管、监控大屏、告警降噪、三类诊断、自愈审批执行回滚、工单通知值班、权限安全审计、平台自运维。
- **剩余可开发**：P3（自接入 + 版本管理）、流式 RPC 代理、P4（TLS + 对外）。
- **不在开发范畴**：集群侧 exporter、准入决策、生产部署、分区 DDL、时区重构。
