# Agent 化改造：开发功能清单（Roadmap）

> 状态：**开发计划**（2026-08-26 老板确认架构后修正）
> 依据：`AGENT-EVALUATION.md`
> **核心定位（老板 2026-08-26 拍板）：**
> - **Agent = 只有 Pod 报警自愈**（资源/编排层，平台能自动执行 → 诊断 + 判断 + 自愈 + 审核闭环）
> - **应用诊断、数据库诊断 = 诊断能力**（只能诊断出结论/方案，做不了 agent；作为 agent 的工具/数据源 + 独立用户入口）

---

## 架构总览（修正后）

```
┌─────────────────────────────────────────────────────┐
│  Pod 报警自愈（唯一 Agent）                            │
│  告警 → 诊断 → 判断根因层 → 执行决策 → 自动执行/审核     │
│      │                                              │
│      ├── 根因在资源层(A) → 自动自愈 / 审批             │
│      ├── 根因在应用层(B) → 调「应用诊断」出建议 → 转发布 │
│      ├── 根因在数据库层(C) → 调「数据库诊断」出方案 → 转DBA│
│      └── 根因在基础设施(D) → 工单/值班                 │
└─────────────────────────────────────────────────────┘
          ▲ 调用                    ▲ 调用
   ┌──────┴──────┐          ┌──────┴──────┐
   │ 应用诊断能力  │          │ 数据库诊断能力 │
   │ (诊断,非agent)│          │ (诊断,非agent)│
   └─────────────┘          └─────────────┘
```

**三个能力的关系**：
1. **报警自愈 = Agent**（唯一）：自动闭环，根因分层决策，能自动就自动、要人审就审核
2. **应用诊断 = 诊断能力**：会话式多轮诊断，只出结论+建议（改代码走发布）；被 Agent 调用 + 用户手动入口
3. **数据库诊断 = 诊断能力**：只出方案（DBA 执行）；被 Agent 调用 + 用户手动入口

---

## 开发清单

### P0：诊断能力工具化（打地基，供 Agent 和诊断助手共用）

| 编号 | 功能 | 涉及服务 | 说明 |
|---|---|---|---|
| P0-1 | 统一工具注册表 | api-server | 把应用诊断工具（exec_in_pod/describe/logs/指标）、DB 采集、知识库检索封装成统一工具，新增工具=注册一条定义 |
| P0-2 | 工具调用护栏 | api-server + executor | 白名单 + 参数 schema 校验 + 全量审计（防 LLM 越权/乱调） |
| P0-3 | 诊断入口保留 | api-server + frontend | 诊断助手/诊断中心作为独立入口不变，能力复用工具注册表 |

### P1：报警自愈 Agent 化（核心，只做这个）

| 编号 | 功能 | 涉及服务 | 说明 |
|---|---|---|---|
| P1-1 | Agent 决策循环（ReAct） | ai-service + api-server | 报警自愈的「诊断→调工具→判断→决策」多轮循环；应用/DB 诊断能力作为工具被调用 |
| P1-2 | 执行决策矩阵落地 | api-server | 根因分层（A 资源/B 应用/C 数据库/D 基础设施）→ 执行域路由 + 自动化边界判定 |
| P1-3 | 规则引擎 + 影子模式 | api-server + frontend | 自动化边界可配置、可演进：规则库 CRUD + 默认拒绝 + 新规则影子试跑 |
| P1-4 | 循环抑制升级 | api-server | 反复自愈失败 → 停自动转人工（治标不治本兜底） |
| P1-5 | 任务记忆 | api-server + ai-service | 同资源历次诊断/自愈/审批记录注入上下文，跨告警复用 |

### 不做（明确排除）

| 项 | 原因 |
|---|---|
| 应用诊断"升级成 agent" | ❌ 应用只能诊断，改代码走发布，平台不自动执行 |
| 数据库诊断"升级成 agent" | ❌ 数据库只给方案，DBA 执行，平台不碰数据 |
| 阶段 2 全自主编排 | 缓行（等 Agent 跑稳 + 数据积累后再议） |
| 发布系统对接（B 层闭环） | 后续可选，需先确认发布系统选型 |

---

## 开发顺序

```
P0-1 → P0-2 → P0-3        （诊断能力工具化）
  ↓
P1-1 → P1-2 → P1-3        （Agent 核心：循环 → 决策矩阵 → 规则引擎）
  ↓
P1-4 / P1-5               （护栏补强，可并行）
```

> 依赖：P1-2（决策矩阵）是 Agent 中枢，P1-1 的循环要依赖它产出根因层判定；P1-3 依赖 P1-2。
