## 一、仪表盘改造（Dashboard v2）

### 1. 目标布局

```
┌───────────────────────────────────────────────────────────┐
│ 顶部栏：项目筛选 | 集群筛选 | 时间范围 | 刷新 | 全局健康分  │
├───────────────────────────────────────────────────────────┤
│ KPI 行(7)：集群数 | 活跃告警 | 自动处理 | 待人工 | DB异常 | 成功率 | MTTR │
├──────────────────────────────┬────────────────────────────┤
│ 告警趋势（折线/堆叠面积）2/3  │ AI 诊断结果分布（环形）1/3  │
├──────────────────────────────┼────────────────────────────┤
│ 实时告警流 / 待处理列表 2/3   │ Top 告警类型排行（条形）1/3 │
├──────────────────────────────┼────────────────────────────┤
│ 异常 Pod Top N（表格）1/2     │ 数据库健康概览 1/2          │
├──────────────────────────────┼────────────────────────────┤
│ 自动处理动作统计/时间线 1/2   │ 集群资源水位 Top 1/2        │
└──────────────────────────────┴────────────────────────────┘
```

### 2. 模块明细

| 区域 | 内容 | 数据源 / 口径 |
|---|---|---|
| 顶部栏 | 项目筛选、集群筛选、时间范围、刷新按钮、**全局健康分**、**平台健康（右上角）** | 项目按绑定的集群+命名空间过滤（`ProjectClusterNS`）；时间范围可切；刷新手动+自动；**平台健康靠 k8s 探针探活、仪表盘右上角显示**（不单独做模块） |
| KPI 行 | 集群数、活跃告警、自动处理、待人工、**DB异常**、成功率、MTTR | 集群数=`cluster_total`；活跃告警=`alert_pending`；**自动处理=近一年累计**（自愈+重启+伸缩+回滚）；待人工=`manual_pending`；**DB异常=`DBConnection.status='failed'` 数**；成功率=`heal_rate`/`plan_success_rate`；MTTR=`mttr_minutes` |
| 告警趋势 | 折线/堆叠面积（新增 / 已解决 / 自愈） | `Alert` 按时间分桶（随「时间范围」） |
| AI 诊断结果分布 | 环形：**可自愈 / 需审批 / 需人工 / 诊断失败** | `Alert.status` + `manual_required` + 诊断结果 |
| 实时告警流 | 未处理告警滚动列表 | `Alert` pending/awaiting_approval |
| Top 告警类型 | 条形排行 | `Alert.fault_type` 计数 |
| 异常 Pod Top N | 表格：**有告警的 Pod（含刚重启）** | `Alert`(pod) + RESTARTS；刚重启（OOM/探针）**自动 AI 诊断 → 告警通知（不审批，见 N5）** |
| 数据库健康概览 | 表格/卡片：各 DB 连接状态 + 指标 | `DBConnection` + `DBMetricSnapshot` |
| 自动处理动作统计 | 计数：**自愈 / 重启 / 伸缩 / 回滚** | 执行记录 / 审计 |
| 自动处理时间线 | **最近 6 条，时间倒序** | 同上 |
| 集群资源水位 Top | 各集群 CPU / 内存 / Pod 数排行（点击进集群） | `cluster_details`（现成） |
| ~~接入项目健康评分~~ | **不做**（老板拍板移除） | — |

### 3. 交互与性能

- **刷新**：前端轮询 **5s**；后端缓存 **15s**（现状 15s/30s → 提速）。
- **筛选**：项目筛选按「项目绑定的集群 + 命名空间」过滤，**不与集群筛选联动**；集群筛选独立；时间范围可切。
- **全局健康分**：0~100 加权 = **集群健康 40% + 活跃告警 30% + DB 健康 30%**。

## 三、已确认（需求锁定 2026-09-18）

- ✅ **KPI 口径**：「自动处理」= 近一年累计；其余 KPI（集群数/活跃告警/待人工/DB异常）当前态，成功率/MTTR 随时间范围。
- ✅ **N5**：不需审批；按 **RESTARTS** 判断 OOM/探针导致的重启，**直接 AI 诊断 → 诊断结果告警通知**。
- ✅ **布局第 6 行右侧**：换为「**集群资源水位 Top**」（各集群 CPU / 内存 / Pod 数排行）。
