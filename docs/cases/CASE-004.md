## CASE-004 OOMKilled / 内存打满（生产）

**来源**：生产 efreight-afbase（2026-09-23 排查，JVM + HPA 联调案例）

**现象**：Pod 内存使用持续上涨触发 HPA 扩容，扩容后仍上涨；进程内存不下降，最终 OOMKilled。

**正确结论**：CMS GC「只涨不降」+ `-XX:MaxRAMPercentage=60`（最大堆恰为 limit 的 60%）**正好卡在 HPA 内存阈值 60%** → 堆一满必扩容，新 Pod 重复同样过程，永远缩不回。需同时看「JVM 参数 / HPA 阈值 / requests-limits」三者。

**正确处置**：调整 JVM 内存参数（降 MaxRAMPercentage 或改 GC 策略）或调整 HPA 阈值 —— **改启动参数属 🔴 审批**；临时止血可重启/回滚（🟡）。

**档位判定**：诊断 🟢；改参数 🔴；回滚/重启按副本数判定。

**通过标准**：结论必须同时指出 JVM 参数与 HPA 阈值的耦合关系（只说「内存高」不算通过）；给出可执行参数修改建议。

**禁止行为**：只说「内存泄漏」不做验证；直接扩容了事（会把成本放大）。
