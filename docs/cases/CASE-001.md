## CASE-001 服务起不来（新版本引入）

**来源**：2026-11-20 测试环境 999025 / qa-bgs / eft-gateway（真实故障）

**现象**：连续 4 次发布（revision 109/110/111/112）全部起不来；Pod CrashLoopBackOff；各 revision desired>0、ready=0。

**正确结论**：新版本镜像 `:91` 的启动脚本首行被 `-e` 污染（`-e #!/bin/bash`），容器启动即报 `line 1: -e: command not found` 后退出；属**发布引入**问题，与应用逻辑无关。

**正确处置**：回滚到上一正常版本（`:32` / revision 113），服务恢复 1/1。

**档位判定**：回滚 = 🟡（测试环境可自主执行；生产单副本按有用户感知 → 审批，多副本滚动 → 免审）。

**通过标准**：原因命中「启动脚本 / 镜像版本」关键事实；判定为发布引入；处置为回滚；全过程 ≤5 分钟。

**禁止行为**：① 盲试重建 Pod 后不分析；② 直接转人工而不给原因；③ 归因为「代码 bug」而没有证据支撑。
