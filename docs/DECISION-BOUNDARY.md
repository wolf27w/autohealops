# 决策与审批边界方案：风险评分 + 审批升级链

> 状态：**方案确认中**（2026-08-20 老板讨论定稿，待开发）
> 定位：替换现有「操作类型 × 时间段」决策策略（DecisionPolicy 四档时段），改为**纯风险评分驱动**，配审批超时升级链。

## 老板拍板的决策（2026-08-20）

1. **时间段不影响决策**，只由操作风险决定（去掉 working_hours/off_hours/weekend/holiday 四档策略）
2. **四维风险评分**：操作类型 × 资源级别 × 影响面 × 环境权重，算出风险分 → 映射风险等级 1-5 级
3. **审核阈值可配**：管理员设"X 级及以上需审核"，X 级以下免审自动执行（如设 4 级 → 1/2/3 免审）
4. **审批分级**：1/2/3 级单人审；4/5 级双人审（风险高）
5. **超时升级链**：20 分钟未审 → 转下一个值班人 + 重新推送审批卡片（钉钉/企微/飞书）→ 值班人轮完 → **管理员兜底**
6. **AI 能力兜底**：AI 完成不了的操作连续 3 次失败 → 强制人工审核（与风险等级无关）
7. 评分值/阈值/等级分段**全部平台可配**，运行后按实际调整

## 一、风险评分模型

```
风险分 = 操作类型分 + 资源级别分 + 影响面分 + 环境权重分
```

### ① 操作类型（复用 analyze_operation_type）

| 类型 | 分值 |
|---|---|
| READ | 0 |
| UPDATE（重启/rollout/scale/set） | 10 |
| CREATE | 20 |
| DELETE | 30 |

### ② 资源级别（从命令解析目标资源）

| 资源 | 分值 |
|---|---|
| pod | 5 |
| configmap/secret | 15 |
| deployment/statefulset/daemonset | 25 |
| service/ingress | 25 |
| namespace/集群级 | 40 |

### ③ 影响面（查资源副本数/类型）

| 情况 | 分值 |
|---|---|
| 多副本（replicas≥2） | 0 |
| 未知/无法判断 | 5 |
| 有状态（statefulset） | 10 |
| 单副本（replicas=1） | 15 |

### ④ 环境权重（集群创建时打 env_tag 标签）

| 标签 | 分值 |
|---|---|
| qa（测试） | 0 |
| release（预生产） | 10 |
| prod（生产） | 20 |

- 集群表加 `env_tag` 字段（qa/release/prod），admin 创建/编辑集群时配置
- 一个集群一个环境（无 namespace 级覆盖）

### 等级映射（分段可配）

| 风险分 | 等级 |
|---|---|
| 0-20 | 1 级 |
| 21-40 | 2 级 |
| 41-60 | 3 级 |
| 61-80 | 4 级 |
| 81+ | 5 级 |

## 二、决策流程

```
修复方案（steps）
   ↓ 逐条算风险分 → 取最高分 → 映射等级
   ↓
等级 < 审核阈值 → 免审自动执行
等级 ≥ 审核阈值 → 创建审批（4/5 级双人 / 1-3 级单人）
   ↓
审批通过 → 执行；拒绝 → 终止转人工
```

- 高危关键词（delete 服务级等）仍强制至少单人审批（兜底保留）
- 同一告警 AI 连续 3 次失败 → 强制人工审核（不依赖等级），走值班人推送（与审批同一通道）

## 三、审批升级链

```
创建审批 → 值班人列表（当天 on_duty 值班人）
   ↓ 一级审核
单人（1-3级）：1 人通过即过；双人（4/5级）：2 人独立通过
   ↓ 20 分钟未审（超时时间可配）
转下一个值班人 + 重新推送审批卡片（钉钉/企微/飞书）
   ↓ 值班人轮完
管理员兜底（最后一道）
   ↓
通过 → 执行 / 拒绝 → 终止
```

### 改动点（相对现有 approval_service）

- Approval 表加字段：`current_approver_index`（当前轮到第几个）、`last_notified_at`（上次推送时间）
- timeout_handler：30 分钟一刀切标 timeout → 改为 20 分钟升级下一位 + 重新推送；轮完转 admin
- 值班轮转：复用 on_duty 值班人列表
- 超时时间、审核阈值、风险分值/分段 → 全部平台可配（决策策略配置页）
- 审批反馈通道（钉钉/企微/飞书 + 文本/按钮 + 长连接/回调）→ 见 `MESSAGING.md` 消息通道方案

## 四、数据模型变更

1. `clusters` 加 `env_tag` 字段（qa/release/prod）
2. `approvals` 加 `current_approver_index` / `last_notified_at`
3. 决策参数配置表（或复用 system_settings）：风险分值、等级分段、审核阈值、超时时间
4. `DecisionPolicy`（四档时段）废弃或改造为「审核阈值配置」

## 五、参数配置化（全部平台可配，管理员在平台修改）

- 风险分值（四维）、等级分段、审核阈值、超时时间（默认 20 分钟）
- 慢 SQL 阈值（默认 1s）、采集频率（默认 5 分钟）——连接级
- 诊断报告保留时长（默认 90 天）
- 数据库只读账号 SQL 模板（平台提供，管理员在库上执行）
