## 二、各项口径与验收

### P1-1 R10 收尾（提示词模板）
- **灰度比例**：`prompt_templates` 加 `gray_pct`（0~100）。auto 来源模板生效时按集群+故障 hash 分流：命中灰度才用新模板，否则回退 `parent_id`/上一版。默认 100（不改变现有行为）。
- **版本 diff**：接口按 `parent_id` 链取历史版本，返回两个版本的 `system_prompt`/`user_prompt_template` 行级 diff（unified），前端弹窗展示。
- **试跑**：用 `sample_vars` + 指定变量值渲染模板，返回渲染结果与缺失变量（不调用模型）。
- 验收：`py_compile` / `npx tsc` 通过；接口冒烟（diff 返回行、试跑返回渲染文本、gray_pct=0 时回退旧模板）；不影响现有诊断链路。

### P1-2 get_setting 缓存
- 进程内 TTL 10s；`update_settings` 后立即失效；敏感字段仍解密返回。
- 验收：连续调用只有首次查库（打日志验证），改设置后 1 次内生效；`ci_check` 全绿。

### P1-3 DB 配置缺失类告警冷却
- 错误特征（`agent 配置里没有 key` / `未下发` / `无在线 agent`）→ 归为「配置类」；
- 配置类告警在同库同故障「最近一次已解决且 ≤60 分钟」时不再新建（只累加原单 `event_count`），避免人工解决后 1 分钟必重建；
- 非配置类（真实连接失败）保持原逻辑不变（不含冷却）。
- 验收：单测覆盖三类错误 + 非配置类路径；真库冒烟：解决后 60 分钟内不再新建。

### P2-1 R14 pull 模式
- agent 新参数 `-mode=push|pull`（默认 push，行为不变）；pull 模式监听 `:9100` 提供 gRPC（复用现有 ExecutorService），不再主动连平台。
- 平台侧 `clusters` 加 `agent_mode`(push/pull) + `agent_pull_url`；`executor_client` 按集群模式选择「隧道」或「直连 pull 地址」。
- 验收：push 集群零回归；pull 集群（可用测试集群临时 Deployment 模拟）HealthCheck/ListPods/ListNamespaces 全通。

### P2-2 平台多副本

## 五、新增需求（2026-11-11 老板拍板）

### R31 诊断会话共享（默认私有，可共享到同 namespace）

**口径**：谁建的会话谁看（默认私有）；**可选**共享给「同集群 + 同 namespace 有读权限」的用户。
用途：运维值班交接——A 排查过的问题，同 namespace 的 B 能接手。

**改动点**
1. 迁移：`diagnosis_sessions` 加 `shared`(bool, 默认 0) / `shared_at` / `shared_by`
2. `GET /agent/sessions`：可见条件 = 自己的 ∪（shared=1 且 该集群/namespace 在调用者权限内）；admin 仍额外可见 `source=proactive`
3. `GET /agent/sessions/{id}/messages`：owner / shared 且有权 / admin 可读，其余 403
4. 新接口 `POST /agent/sessions/{id}/share`（owner 或 admin）`{"shared": true|false}`
5. 前端：会话头部加「共享到本 namespace」开关；列表项显示「共享」标签
6. **顺带加固**：列表按**当前权限**过滤——权限被回收后，历史会话不再出现在列表里（自己建的也过滤）

**验收**
- 同 namespace 的另一个普通用户：共享后能看到该会话且能读消息；取消共享后消失
- 不同 namespace / 无权限用户：始终看不到（接口 403）
- 收回 namespace 权限后：会话从列表消失
- admin 不受影响；`ci_check` 全绿
