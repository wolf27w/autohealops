## 1. 排序原则

1. 真 Bug / 半天能收的先做（R9），避免长期带病运行。
2. 同类需求合并成一批，减少迁移和回归次数（数据库线、主机线、诊断线）。
3. **agent 侧改动集中一次发版**（第 3 批的 `ListNamespaces` 与主机线若有 agent 改动一起排），避免反复升级。
4. 动接入层的（R14 双接入、R2 多副本）放最后，且不并行。
5. 提示词体系（R10）必须最后做，吸收 R11/R12/R13/C2 的落地经验。

1. 每批结束：`./scripts/ci_check.sh` 全绿 + 真实接口冒烟 + 按路径 `git commit`。
2. agent 镜像升级：测试集群 → UAT → 生产，每步保留上一版 tag。
3. proto 改动单独立项提交（Go/Python 双端重新生成，先验证再合并其它改动）。
4. 数据库迁移：先备份再变更；删表前确认数据已导出。
