# Agent 自主边界（什么时候自己修、什么时候要人批）

> 老板 2026-11-23 定稿口径。本文是**审所有 agent 需求的标准**：任何动作先归类到四档之一，再谈实现。
> 原则：**AI 负责"想明白该干什么"，规则负责"这个能不能干"。** 智能在 AI，授权在制度。

---

## 一、判定口诀

> **能一键还原吗？只影响这一个服务吗？**
> - 两个都是 → 免审批，直接做
> - 有一个不是 → 必须人批
> - 碰到 代码 / 数据 / 权限 / 删除 → 根本不做，只出方案

再叠加一条：**把握要够**（AI 给出的 confidence ≥ 80%）才允许进入自动档；把握低一律转人工。

---

## 二、四档清单

### 🟢 免审批，自动执行（做完通知）

| 动作 | 典型场景 |
|---|---|
| 所有只读查询 | 日志、指标、事件、配置、变更记录、巡检、EXPLAIN、元数据 |
| 重建 Pod | 卡死、偶发崩溃、Terminating 卡住 |
| 单服务回滚版本 | 回到上一个正常版本（需存在健康基线） |
| 补镜像拉取凭据 | ImagePullBackOff |
| 摘流 / 摘健康检查 | 服务已不可用，先停止给流量 |

### 🟡 免审批，但必须事后报备（附分析结论与依据）

| 动作 | 理由 |
|---|---|
| 回滚**生产**环境服务 | 可逆，但影响整服务，必须留痕 |
| 重启整个工作负载（全部 Pod） | 影响面大于单 Pod |
| 临时扩容 2 倍以内 | 花钱占资源，但可逆 |

### 🔴 必须审批

| 动作 | 审批人 |
|---|---|
| 改配置（探针 / resources / 环境变量 / ConfigMap） | 服务负责人或值班 |
| 缩容、扩容超 2 倍 | 服务负责人 |
| 节点操作（cordon / drain / 重启节点） | 运维主管 |
| 跨服务批量操作 | 运维主管 + 服务负责人 |
| 生产环境任何不可逆操作 | **双人** |

### ⛔ 平台永不执行（无审批通道，只出方案）

| 动作 | 谁做 |
|---|---|
| 改代码、发新版本 | 开发 |
| 数据库 DDL / 索引变更 / 数据修改删除 | DBA |
| 删 PVC、删存储数据 | DBA / 运维 |
| 改权限、改网络策略、改安全配置 | 安全 + 运维 |
| 删命名空间、删集群资源 | 运维走变更流程 |

## 三、白名单制（不是黑名单制）

**新动作默认要审批**，只有登记在「免审批清单」里的才能自动执行。

- 加白名单 = 有人主动决策（有意识）
- 黑名单 = 新动作默认放行（迟早漏）

新能力上线流程：提议动作 → 评估风险档位 → 登记进对应档 → 才能使用。

---

## 四、审批配套规则（防卡死、防失控）

| 情况 | 处理 |
|---|---|
| 审批超时无人响应 | **默认拒绝**，不默认放行；同时上报上级审批人 |
| 夜间 / 节假日 | 仅老板显式授权的动作类型可免审批，其余一律等待 |
| 审批被拒 | agent 停止，不换招硬来；记录结论与拒绝原因 |
| 同一问题反复修 | 同一服务 10 分钟内只自动处理 1 次，第 2 次必须人批 |
| 修完未恢复 | 立即停手转人工，**禁止连续试错** |
| 每次决策 | 记录判定档位、把握度、依据（可审计、可复盘） |

## 五、两个已定口径

1. **「重启整个服务」= 🟡 报备**，不是 🔴。因为可逆，且是最高频动作，走审批会把值班拖死。
2. **环境分档**：测试环境 🟡 可放宽为自动；生产环境 🟡 一律报备、🔴 一律双人。同一动作，环境不同档位不同。

---

## 六、数据库域专用（只读）

- 账号只读，**不具备任何写能力** → L4/L5 之外不存在"执行"问题
- 产出物 = 可执行工单：证据 + 根因 + 要执行的 SQL + **回滚 SQL** + **验证 SQL** + 影响面
- 审批通过后由 DBA 执行，平台**记录执行结果**（成功/失败/耗时）
- 指标口径：定位准确率 + 方案采纳率 + 人工节省时间（不是自动修复率）

---

## 七、应用域指标口径

- 自动恢复率、MTTR、误修率（改错配置算误修）
- 转人工的必须附完整分析结论与已排除项，否则视为 agent 失败
